# 자율은 곧 무인(無人)이 아니다: 하네스가 자기 마일스톤을 스스로 출고하게 두었다

**언어:** [English (정본)](./BLOG-shipping-a-milestone-autonomously.md) · 한국어

*[Agented](https://github.com/ca1773130n/Agented)의 플래닝 하네스를 6개 페이즈짜리 마일스톤 — 설계 명세부터 병합된 PR까지 — 에 겨누고 그냥 돌렸다. 하네스는 사람이 기능 코드를 한 줄도 쓰지 않은 채 3개의 의존성 웨이브에 걸쳐 6개 페이즈 전부를 계획하고, 만들고, 코드 리뷰하고, 병합했다. 그리고 두 번 멈췄다. 두 번 다 기능 작업이 실패한 게 아니라 오케스트레이터가 자기 git 배관에서 자빠진 것이었다. 그 비대칭이 이야기의 전부다: 자기개선 하네스에서 가장 어려운 버그는 무엇을 만드느냐가 아니라, 만드는 일을 수행하는 층에 있다.*

## 그 실행(run)

마일스톤은 Agented v0.8.0 — "팀 하네스 & 자가 개선"이었다. 프로젝트가 자기 하네스 프리미티브를 생성하고, 모든 슈퍼에이전트 대화를 기본으로 [GetResearchDone](https://github.com/ca1773130n/Agented)(GRD)을 통해 돌리며, 반복되는 운영자 요청을 자동으로 스킬화하는 층이다. 6개 페이즈, 26개 요구사항, 승인된 설계 명세 하나.

`gd autopilot 17-22`를 호출하고 키보드에서 손을 뗐다. 오케스트레이터는 로드맵에서 의존성 그래프를 계산해 페이즈를 3개 웨이브로 묶었다:

```
웨이브 1:  [17]              forge 생성 표면
웨이브 2:  [18, 19, 22]      스케치 라우팅 · GRD 드라이버 · 자동 스킬
웨이브 3:  [20, 21]          GRD 프론트엔드 연동 · 원클릭 셋업
```

한 웨이브 안의 독립 페이즈들은 각각 자기 git 워크트리에서 병렬로 돈다 — 파일 변경이 절대 충돌하지 않도록. 각 페이즈는 같은 파이프라인을 거쳤다: 계획 → 실행 → 단순화 → PR 생성 → 코드 리뷰 → 리베이스 & 병합 → 마무리. 6개 페이즈, 6개 PR(#213–#218), 모든 리뷰가 경고만(warnings-only), 블로커 0. 게이트도 버텼다: 표적 백엔드 스위트는 **1222 통과, 0 실패**로 끝났고, 프론트엔드 스위트는 알려진 베이스라인 실패 7개만 그대로, 신규 실패 0. 사람이 일주일 걸렸을 마일스톤이 오후 한 나절에 스스로 병합됐다.

여기까지가 미래처럼 들리는 부분이다. 진짜 교훈은 다음이다.

## 멈춘 두 지점

두 번의 멈춤은 모두 실행 후 파이프라인 — 병합 단계 — 에서 일어났고, 둘 다 병합되는 코드와는 아무 상관이 없었다.

**첫 번째는 실행 전체를 죽였다.** 페이즈 17은 깔끔하게 빌드되고 리뷰를 통과했는데, 파이프라인이 페이즈 워크트리 안에서 `gh pr merge --delete-branch`로 PR을 병합하려 했다. `gh`의 브랜치 정리는 병합된 브랜치를 로컬에서 지우려고 저장소의 기본 브랜치를 체크아웃한다 — 그런데 `main`을 보유하지 않은 연결된(linked) 워크트리 안에서는 `main`을 체크아웃할 수 없다. git은 거부했다: `fatal: 'main' is already used by worktree`. PR은 이미 GitHub에서 병합됐는데도, 오케스트레이터는 0이 아닌 종료 코드를 보고 페이즈를 실패로 선언하고 6개 페이즈 전부를 멈췄다. 기능은 멀쩡했다. 하네스가 문을 나서다 제 발에 걸려 넘어진 것이다.

**두 번째는 더 조용하고 더 나빴다. 멈추는 대신 상태를 오염시켰기 때문이다.** 페이즈가 마무리될 때 자기 로드맵 행을 "완료"로 도장 찍는다. 그 스탬퍼는 고정된 열 배치 — `| 페이즈 | 이름 | 상태 | 날짜 |` — 를 가정한 위치 기반 정규식을 썼다. 우리 로드맵 표는 더 넓어서(요구사항과 의존성 열을 갖는다) 도장이 엉뚱한 칸에 찍히며 실제 데이터를 "완료"라는 단어로 덮어썼다. "성공한" 실행이 제 플래닝 원장을 조용히 틀리게 남긴 것이다. 우리가 전에 쓴 바로 그 실패 양식이다: [망가진 것 위에 찍힌 초록 체크](https://github.com/ca1773130n/Agented/blob/main/BLOG-self-improving-harness.md). 파이프라인은 성공을 보고하면서 자신이 한 일의 기록을 조용히 훼손했다.

세 번째는 더 가벼운데, 첫 번째를 고친 뒤 드러났다: 로컬 `main`을 갓 병합된 원격과 다시 맞추는 병합 후 단계가 auto-stash 리베이스를 쓰는데, 이는 *추적되는(tracked)* 파일만 보호한다. 오케스트레이터 자신이 작업 트리에 써둔 스크래치 파일이 체크아웃을 막아, 리베이스가 경고와 함께 중단되고 `main`이 원격보다 뒤처진 채 남았다. 치명적이지는 않지만, 마지막에 사람이 fast-forward 해주지 않으면 실행이 자기 루프를 완전히 닫지 못한다는 뜻이다.

## 사람의 일이 한 층 위로 올라갔다

이 중 어느 것도 기능 버그가 아니다. 6개 페이즈의 diff를 전부 리뷰해도 결코 못 찾는다 — diff 안에 살지 않기 때문이다. 그것들은 diff를 *생산하는* 기계 안에 산다. 그래서 이 실행이 사람에게 실제로 요구한 일은 "기능을 짜라"가 아니었고, "기능을 리뷰하라"조차 아니었다. 그것은: 오케스트레이터 자신의 소스를 읽고, 왜 병합 단계가 워크트리에 안전하지 않은지 찾아내 고치고, 다시 돌려라. 그다음 왜 상태 스탬퍼가 열에 무지한지 찾아 고치고, 이미 망가뜨린 행들을 복구하라.

둘 다 GRD 소스에서 고쳤다 — 워크트리에 적대적인 플래그 없이 병합하고 원격 브랜치를 직접 삭제하도록, 스탬퍼가 위치 대신 헤더로 대상 열을 찾도록 — 수정을 커밋하고 다시 돌렸다. 자동 재개가 이미 병합된 네 페이즈를 건너뛰고 마지막 둘을 완주까지 끌고 갔다. 루프는 닫혔다. 그런데 *누가* 닫았는지 보라. 자기개선 하네스가 제 오케스트레이터를 스스로 고친 게 아니다. 사람이, 오케스트레이터의 저장소에서, 오케스트레이터 두 실행 사이에 고쳤다. 자율은 기능 층에서는 진짜였고 메타 층에서는 전혀 없었다.

이것이 "자율"이라는 단어가 덮어버리는 구분이다. 오토파일럿은 모든 제품 결정을 내리고, 모든 테스트를 쓰고, 모든 PR을 우리 없이 병합했다는 의미에서 자율적이었다. 그러나 *무인*은 아니었다. 제 배관이 실패하는 순간, 루프 밖에 선 사람만이 루프를 돌리는 그것을 고칠 수 있었기 때문이다. 하네스는 종일 기능을 만들 수 있다. 그러나 아직 자기 병합 명령이 자기 워크트리 전략과 호환되지 않는다는 걸 알아채고, 진단하고, 자기를 패치하지는 못한다. 그 두 능력 사이의 간극이 정확히 "자율"과 "무인" 사이의 간극이며, 오늘날 에이전트 오토파일럿을 출고하는 거의 모두가 그 간극에 조용히 사람을 세워두고 있다.

## 그것이 출고한 것은 결국 같은 종류의 기계다

재귀는 일화보다 더 깊다. 하네스가 출고한 마일스톤 자체가 *자가 개선 기계*이기 때문이다. 페이즈 22 — 웨이브 2에서 자율적으로 만들어진 — 는 반복 요청 감지기다: 완료된 세션을 5종 세션 전부에 걸쳐 지켜보며 운영자의 요청을 임베딩하고, 검증된 성공 에피소드를 배경으로 같은 요청이 세 번 반복되면 새 스킬을 제안한다. [Hermes Agent](https://github.com/NousResearch/hermes-agent)의 자가 작성 스킬을 본떴지만, [ToxicSkills 위협 모델](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/)이 요구하는 방식으로 게이트를 걸었다: 신뢰도 하한, 검증 요건, 무엇이든 쓰기 전 프롬프트 인젝션·비가시 유니코드 스캔, 그리고 루프가 운영자가 수정한 스킬을 절대 덮어쓰지 않도록 하는 출처 해시. 하네스는 자율적으로, 자신의 조금 더 자율적인 버전을 만들었다 — 그리고 새 행동을 디스크에 쓰는 부분은 잠가서 출고하도록 우리가 보장했다. 스킬을 써서 학습하는 에이전트는 구조적으로 [의존성을 다운로드한 것](https://github.com/ca1773130n/Agented/blob/main/BLOG-self-improving-harness.md)이기 때문이다.

이것이 올바른 형상이다. 기능 층은 복리로 쌓인다: 각 마일스톤이 다음 마일스톤을 더 싸게 만든다. 그러나 메타 층은 아직 스스로 복리로 쌓이지 않는다. 자동 스킬 루프는 오늘은 못 했던 스킬을 내일 제안할 것이다. 오케스트레이터는 오늘 부딪힌 것과 같은 부류의 배관 버그를 내일도 부딪힐 것이다 — 사람이 다르게 가르치지 않는 한. 그게 이번 주 우리가 병합 단계와 스탬퍼에 한 일이다.

## 예측

반증 가능하도록 적는다.

에이전트 오토파일럿의 다음 프런티어는 작업의 더 높은 통과율이 아니다. 그것은 메타 층 자가 치유다: 제 병합 단계가 제 워크트리 불변식에서 실패할 때, 그 실패를 하나의 작업으로 다루어 — 자기 소스에서 진단하고, 수정을 리뷰 가능한 diff로 제안하고, 재개하는 — 사람을 위해 멈추지 않는 오케스트레이터. 오토파일럿이 실행 도중 자기 안의 버그를 고치고, 운영자가 그 사실을 나중에 커밋을 읽고서야 알게 될 때, 우리는 프런티어가 넘어섰음을 알게 될 것이다.

12~18개월 안에, 이것을 신뢰할 만하게 해내는 첫 오토파일럿은, 여전히 제 배관에서 멈추는 모든 "자율" 에이전트를 있는 그대로 보이게 만들 것이다: 사람이 조용히 병합 전략을 붙잡아주는 기능 제작기. 이 싸움에서 이기는 팀은, 이번 주 우리처럼, 오케스트레이터 자신의 버그를 부수적 마찰이 아니라 일급 산출물로 다룬 팀 — 그리고 그 버그 하나하나를 에이전트의 믿음에 적용하는 것과 같은 출처 규율로 기록한 팀일 것이다. 오케스트레이터도 감사(audit) 대상 시스템의 일부다. 그것이 스스로를 감사하고 수리할 수 있는 날이, "자율"이 마침내 "무인"을 뜻하게 되는 날이다. 아직은 그렇지 않다. 그렇다고 말하는 사람은, 우리가 그랬듯, 그 간극에 사람을 세워두고 있다.

## 참고

### 플랫폼과 이 실행
- **Agented** — 여기서 설명한 마일스톤의 주인공인 메타 오케스트레이션 층. [github.com/ca1773130n/Agented](https://github.com/ca1773130n/Agented)
- **GetResearchDone (GRD)** — 6개 페이즈를 계획·제작·병합한 플래닝/실행 하네스(`gd autopilot`); 두 멈춤 버그는 실행 도중 그 소스에서 고쳤다.
- **v0.8.0 설계 명세** — 오토파일럿이 실행한 승인된 청사진: forge 생성 표면, 스케치→프리미티브 라우팅, GRD 기본 드라이버, GRD 프론트엔드 전면 연동, 원클릭 팀 하네스 셋업, 반복 요청 자동 스킬.

### 이 글이 잇는 시리즈
- **당신 에이전트의 문제는 메모리가 아니라 출처다.** — 출처 논증과 12개의 침묵 실패 도그푸드. [BLOG-self-improving-harness.md](https://github.com/ca1773130n/Agented/blob/main/BLOG-self-improving-harness.md)
- **Harness-1 이식기** — 일급 빌드 단계로서의 적대적 검증. 함께 출고된 리서치 보고서는 이제 [harness-1-integration.md](./harness-1-integration.md)에 있다.

### 마일스톤이 출고했거나 참조한 기계
- **Hermes Agent** (NousResearch) — 자동 스킬 루프의 모델인 자가 작성 스킬. [github.com/NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)
- **Snyk ToxicSkills 감사** — 자동 스킬 루프를 기본 잠금으로 출고하는 이유. [snyk.io/blog/toxicskills](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/)
- **Voyager** — 감지기 뒤의 임베딩 유사도 스킬 검색 선행 연구. [arxiv.org/abs/2305.16291](https://arxiv.org/abs/2305.16291)
