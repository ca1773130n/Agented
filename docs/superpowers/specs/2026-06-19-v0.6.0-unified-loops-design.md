# v0.6.0 — Unified Loop Control Surface — Design

**Status:** design proposal (awaiting approval before spec → plan).
**Date:** 2026-06-19
**Direction (user-chosen):** *extend* Agented's existing loop primitives (Ralph sessions, goal-loops, GRD autopilot) into **one** user-configurable + observable loop surface; *unify* all three loop patterns — agentic task loops, eval/refinement loops, and cyclic workflows — under a single model.

Grounded in a deep-research pass (6 angles, 27 sources, 23 verified claims, 2 refuted). Key sources cited inline.

---

## 1. Problem

Agented already runs loops three different ways, each with its own config, runner, and UI:
- **Ralph sessions** (`create_ralph_session`, `ralph-loop` plugin) — re-run an agent on a goal.
- **Goal-loops** (`goal_loop_runner`, `resume_goal_loop`) — per-iteration tracking + checkpoint/resume.
- **GRD autopilot** (`gd autopilot N`) — run N phases end-to-end. Plus life-harness rounds.

There's no single way for a user to **design** a loop (set what iterates, when it stops, what it costs), **run** it, and **observe/stop** it. The three share ~80% of their concerns (iterate, exit, budget, state, observe) but duplicate them.

## 2. Research → design principles (evidence-backed)

| # | Finding (source) | Design mandate |
|---|---|---|
| F1 | Ralph = brute-force while-loop, "deterministically bad" but eventually-consistent; great for greenfield (~90% anecdotal), poor on existing code; needs supervision (ghuntley.com/ralph) | Keep task-loops, but **context-reset-per-iteration is a configurable mode**, and surface a greenfield-vs-brownfield expectation. |
| F2 | Context-window discipline is the dominant control lever; quality "clips" well below advertised limits; "one item per loop"; primary context = scheduler that spawns subagents (ghuntley; Chroma "Context Rot") | **Per-iteration context budget** is a first-class knob; default to reset/compact; support scheduler→subagent. |
| F3 | Cyclic graphs need a built-in circuit breaker: LangGraph `recursion_limit` hard-aborts (default 25) (LangGraph docs) | Cyclic workflows get a **per-run iteration cap** + explicit exit-condition edges as the *preferred* stop. |
| F4 | Canonical eval loop = generate→evaluate→refine; exit = evaluator's structured grade (Accepted→END / Rejected+feedback→regen), **NOT** a fixed count (LangGraph evaluator-optimizer) | Eval loop's exit is **quality-gate-first**. **WARNING:** always pair the gate with a max-iter/token fallback (the doc example has none → infinite refinement risk). |
| F5 | Self-critique loops have measured gains: Reflexion 91% pass@1 HumanEval; Self-Refine ~20% avg (arXiv 2303.11366, 2303.17651) | Support reflection/feedback carried across iterations; **prefer grounded signals (tests, rubric-judge)** over pure self-critique for code. |
| F6 | LLM-as-Judge is the scalable scorer but reliability is an open challenge (bias/drift) (arXiv 2411.15594) | If judge is the gate: expose **rubric/structured grade, judge-versioning, human spot-check**; don't trust by default. |
| F7 | Dynamic early-termination (confidence at milestones) cut SE-agent cost **19–55% (avg 32%), ≤0.2% resolution loss** on SWE-bench Verified; max-iter as fallback (arXiv 2601.05777 / EET) | Support **confidence/quality-based dynamic stopping**, not just max-iters. Quantified upside ≈32% cost. |
| F8 | "Token snowball": feeding full history back grows cost super-linearly; stuck agents burn iterations (EET) | **Token/cost circuit breaker + stagnation/no-progress detection** are required primitives. |
| F9 | Reward-hacking/spec-gaming is measurable (0–13.9% across 13 models); sandbox hardening cuts it **−87.7% relative at no capability cost** (arXiv 2605.02964) | **Sandbox hardening** (eval-boundary isolation) is mandatory *especially* once eval-in-the-loop creates a gradeable reward to game. |

## 3. The unifying abstraction — `LoopSpec`

One declarative spec that all three patterns compile to; `goal_loop_runner` becomes the single executor (it already iterates + checkpoints — extend it rather than build new).

```
LoopSpec:
  body:          # what runs per iteration
    kind: agent_task | eval_refine | workflow_step
    ...kind-specific (prompt/agent, or generate+evaluate pair, or graph node)
  exit:          # ordered; first match wins
    - quality_gate:  test_pass | metric{name,threshold} | llm_judge{rubric, judge_version}   # F4,F6
    - done_detection / confidence{threshold}        # F7 dynamic early-termination
    - stagnation:    no_progress_for: N             # F8
    - HARD fallback (always on): max_iterations, token_budget, cost_budget   # F3,F8 circuit breakers
  state:
    context_policy: reset | compact | carry          # F2 default reset/compact
    carry_feedback: bool                             # F5 reflection memory
    checkpoint: bool                                 # reuse goal_loop_runner checkpoints
  sandbox: level (F9 — eval-boundary isolation; required when quality_gate present)
  observability: per-iteration traces + live status + stop/pause/intervene + human gates
```

**Mapping (extend, not rebuild):**
- Ralph session → `body.kind=agent_task`, `context_policy=reset`, exit=budget+done.
- Goal-loop → already this; becomes the reference executor.
- GRD autopilot → `LoopSpec` over phases, exit = phases-complete + optional per-phase gate.
- Cyclic workflow → WorkflowBuilder DAG + conditional back-edges + `max_iterations` (F3).

## 4. User-facing surface

- **Loop Builder** (new panel; reuses existing config patterns): compose a `LoopSpec` — pick body, exit criteria, budgets, eval gate, context policy, sandbox level. Templates for the three patterns.
- **Loop run/control surface**: live per-iteration status, budget consumption (iters/tokens/cost), the *pending* exit condition, and **stop / pause / intervene + human-gate approvals**. Reuses the existing goal-loop iteration UI + SSE streaming.

## 5. Phasing (MVP = phases 1–3)

1. **Model + engine** — define `LoopSpec`; extend `goal_loop_runner` into the single executor honoring exit/budget/context policies; migrate Ralph + goal-loops onto it (backward-compatible). Core circuit breakers: max-iter + token + **stagnation detection** (F3, F8).
2. **Eval-in-the-loop + sandbox** — quality-gate exit (test-pass / metric / LLM-judge w/ rubric + versioning + mandatory budget fallback); confidence-based dynamic early-termination (F4–F7); sandbox hardening for the gradeable reward (F9).
3. **Observability + control** — per-iteration traces, live status, stop/pause/intervene, human gates. (The "run + observe" half.)
4. *(post-MVP)* **Cyclic workflows** — WorkflowBuilder conditional back-edges + recursion cap (F3).
5. *(post-MVP)* **Loop Builder polish** — templates, presets, per-harness budget defaults.

## 6. Open questions (resolve during spec)

- **Stagnation detection algorithm** — output-similarity / repeated-tool-call / plateaued-eval-score? (research named the problem; EET's confidence-τ is one approach, no canonical algo).
- **Durable cross-iteration state** — `goal_loop_runner` already checkpoints; confirm it covers `LoopSpec` state (the LangGraph Checkpointer mapping claim was *refuted* in research — don't assume it).
- **Per-harness budget calibration** — Claude Code vs Codex vs Gemini cost envelopes differ; default thresholds TBD (research flagged $50–100/50-iter Ralph cost vs EET's 32% savings).
- **Build cyclic natively vs adopt LangGraph** — research only verified LangGraph's model; no other framework's unifying schema survived verification (CrewAI claims refuted).

## 7. Non-goals (v0.6.0)
- Not replacing the WorkflowBuilder DAG engine (cyclic is additive, post-MVP).
- Not auto-tuning budgets (manual + sensible defaults first).
- Not full multi-agent loop orchestration beyond the existing scheduler→subagent pattern.
