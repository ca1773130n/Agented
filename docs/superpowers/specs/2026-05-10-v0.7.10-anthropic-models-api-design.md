# v0.7.10 — Direct Provider Models API + Static-Fallback Refresh

## Goal

Replace the stale CLIProxyAPI-mirror static list with a **live `GET /v1/models` call** to each provider, using the stored credential. This way the model list is exactly what the user's account can actually use — no manual curation needed and no stale CLIProxyAPI binary to blame.

## Problem evidence

User reports for Claude (cli_browser auth):
- **Missing latest** — no Claude Opus 4.7 (Anthropic's current frontier)
- **Includes obsolete** — `claude-3-7-sonnet-20250219`, `claude-3-5-haiku-20241022`, `claude-opus-4-1-20250805`, `claude-opus-4-20250514` are listed but the subscription tier no longer serves them.

Root cause: `claude.py::list_models()` returns whatever CLIProxyAPI 6.8.30 advertises, which is its own hardcoded list. The static fallback in this repo mirrors that exact list. Neither updates with Anthropic's catalog.

## Architecture

### Per-backend `/v1/models` calls

Add a new path to `list_models()` in each `backends/*.py` impl in **ai-accounts core**, BEFORE the existing CLIProxyAPI / static-fallback path:

**Claude** — `https://api.anthropic.com/v1/models`
- API key auth → `x-api-key: <key>`, `anthropic-version: 2023-06-01`
- OAuth auth (cli_browser, sk-ant-oat-...) → `Authorization: Bearer <token>`, `anthropic-beta: oauth-2025-04-20`
- Response: `{"data": [{"type": "model", "id": "claude-...", "display_name": "..."}, ...]}`
- Already has parallel pattern in `claude.py::get_usage()` which uses the OAuth bearer header.

**Codex/OpenAI** — `https://api.openai.com/v1/models`
- API key → `Authorization: Bearer <key>`
- ChatGPT subscription (oauth_device) → use stored OAuth bearer
- Response: `{"data": [{"id": "gpt-...", "owned_by": "..."}, ...]}`
- For ChatGPT-auth, the response is filtered by what the subscription serves; for API-key, all models. Same endpoint, same shape.

**Gemini** — already done in `gemini.py::list_models()`. No change.

**OpenCode** — local config; no equivalent provider endpoint. Existing logic preserved.

### Fallback chain (post-v0.7.10)

```
1. /v1/models direct (NEW — primary)
2. CLIProxyAPI live list (existing)
3. Static curated fallback (existing — refreshed below)
```

If 1 returns >0 models → return those. Otherwise continue.

### Static fallback refresh

Update `claude.py::list_models()` static list to:
- Include `claude-opus-4-7` and `claude-sonnet-4-7` (assumed current frontier — verify against `/v1/models` response in the actual environment)
- Drop `claude-3-7-sonnet-*`, `claude-3-5-haiku-*` (deprecated)
- Drop `claude-opus-4-1-*`, `claude-opus-4-20250514` (subscription users can't use)
- Keep `claude-opus-4-6`, `claude-opus-4-5`, `claude-sonnet-4-6`, `claude-sonnet-4-5`, `claude-haiku-4-5`

Final static list shrinks to ~7 current-or-recent-stable entries.

The static list is best-effort — once the live `/v1/models` path works for both auth types, the static one rarely fires. But when it does (offline, throttled, etc.) we want it to be sane, not stale.

### Discovery method telemetry

The v0.7.9 `discovery_method` cache column now picks up a new value: `"provider_api"`. The UI's "via X" label reflects this so the user knows when they're getting the authoritative list.

## What this is NOT

- A "models registry" or marketplace. We're calling each provider's published endpoint, not curating one.
- A subscription-tier resolver. Anthropic's `/v1/models` already filters by what the credential can use.
- A schema change. No DB migration. v0.7.8's cache layer absorbs the new path transparently.

## Out of scope

- Per-account override list (operator manually pinning a model)
- OpenCode native models — this affects only Anthropic / OpenAI direct paths
