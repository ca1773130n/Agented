# v0.7.7 — Super-Agent Activity Inspector

## Goal

Give operators a per-super-agent timeline showing every meaningful event (tool calls, file edits, git actions, model invocations, message turns) with status pills, cost rollup, and drill-down. Closes the "what is this autonomous agent actually doing right now" gap — the missing observability surface for the product's biggest selling point.

## Architecture

**Reuses existing v0.7.0 + v0.7.1 patterns** — no new infrastructure is invented:

- v0.7.0's per-bot health rollup → adapt for per-super-agent rollup
- v0.7.1's trigger payload capture → adapt for super-agent activity event capture
- Existing `super_agent_*` tables + `super_agents_cluster.py` routes already cover CRUD/sessions

### Backend

New table `super_agent_activity` (migration 116):

| Column | Type | Notes |
|---|---|---|
| `id INTEGER PRIMARY KEY AUTOINCREMENT` | | |
| `super_agent_id TEXT NOT NULL` | | logical reference to super_agents.id (no FK CASCADE — keep history) |
| `session_id TEXT` | | optional link to the super-agent session |
| `event_type TEXT NOT NULL` | | `tool_call` / `file_edit` / `git_action` / `model_invoke` / `message_turn` / `decision` / `error` |
| `recorded_at TIMESTAMP NOT NULL` | | |
| `payload TEXT NOT NULL` | | JSON — event-specific details |
| `cost_tokens_in INTEGER` | | optional, for `model_invoke` events |
| `cost_tokens_out INTEGER` | | |
| `cost_usd REAL` | | computed at insert time from existing token_usage tables |
| `status TEXT NOT NULL DEFAULT 'ok'` | | `ok` / `error` / `partial` |
| `error_message TEXT` | | |
| `duration_ms INTEGER` | | |

Indices on `(super_agent_id, recorded_at DESC)` + `(session_id, recorded_at DESC)` + `recorded_at` (TTL).

**New service** `app/services/super_agent_activity_service.py`:
- `record(...)` — insert one event
- `list_for_super_agent(super_agent_id, limit=200, since=None, types=None)`
- `list_for_session(session_id, limit=200)`
- `get(activity_id)`
- `rollup(super_agent_id, window_days=7)` — returns `SuperAgentRollup` (event_count, error_count, total_cost_usd, last_active_at, status_pill, cost_per_event_avg, error_rate)
- `purge_older_than(days=30)` — TTL cleanup

**Wiring**: existing super-agent execution paths (orchestration_service, super_agent_session, conversation_streaming) get one-line `super_agent_activity_service.record(...)` calls at the natural emission points. **No new orchestration logic** — pure observability.

**New routes** in `app_litestar/routes/super_agent_activity.py`:
- `GET /admin/super-agents/{id}/activity?limit=200&since=...&types=...` — list
- `GET /admin/super-agents/{id}/rollup?window_days=7` — rollup
- `GET /admin/super-agents/sessions/{session_id}/activity` — per-session timeline
- All admin-guarded.

**Daily TTL purge** in `lifecycle.py` — mirror v0.7.1's `purge_trigger_events_job` pattern.

### Frontend

**New page** `frontend/src/views/SuperAgentInspectorPage.vue` at route `/super-agents/:id/inspector`:

- Header card — name, status pill, total events, total cost (last 7d), error rate
- Timeline view (chronological list, newest first):
  - Each row: timestamp + event-type pill + 1-line summary + cost (if any) + duration
  - Click to expand → JSON payload + error message if present
- Filter bar — event type (multi-select) + time window (1h/24h/7d/30d) + status (all/error-only)
- Live-poll on 10s interval (no SSE — match v0.7.1 simplicity)

**API client** `frontend/src/services/api/super-agent-activity.ts`:
- `superAgentActivityApi.list(superAgentId, opts)`
- `superAgentActivityApi.rollup(superAgentId, windowDays)`
- `superAgentActivityApi.listForSession(sessionId)`

**Sidebar entry** under the existing super-agents nav: link to the inspector for the currently-selected super-agent.

## Status pill rules

- **Active** — last activity within 5 minutes, no error in last 10 events
- **Errored** — most recent event is an error
- **Idle** — no activity in last 24h
- **Healthy** — recent activity present, error rate < 10% over window

## Out of scope

- New orchestration logic / agent autonomy improvements
- Multi-harness coordination (separate milestone)
- Real-time SSE — poll-based v1
- Per-event drill-down into the actual file diff (link out to existing executions UI is enough)
- Cost configuration UI (uses existing token-usage cost helpers)
