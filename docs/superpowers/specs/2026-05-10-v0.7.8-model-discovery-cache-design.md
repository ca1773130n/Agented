# v0.7.8 — Cached + Auth-Aware Model Discovery

## Goal

Make per-backend model lists **correct, current, and cheap**:
1. Store discovered models in a DB cache with a configurable TTL (default 7 days)
2. Refresh stale entries in a background job — users never wait for discovery
3. Filter the published list by **auth method** so Codex-via-ChatGPT doesn't advertise API-key-only models like `gpt-5.1` / `gpt-5.1-codex-mini`
4. Provide a **manual refresh** endpoint + UI button for force-update

## Architecture

### Data model

New table `model_discovery_cache` (migration 117):

| Column | Type | Notes |
|---|---|---|
| `id INTEGER PRIMARY KEY AUTOINCREMENT` | | |
| `backend_kind TEXT NOT NULL` | | `claude` / `codex` / `gemini` / `opencode` |
| `auth_method TEXT NOT NULL` | | `cli_browser` / `oauth_device` / `api_key` / `subscription` / `unknown` |
| `models_json TEXT NOT NULL` | | JSON array of canonical model IDs |
| `discovery_method TEXT NOT NULL` | | `pty` / `cli` / `cliproxy` / `local_file` / `package` / `mixed` |
| `discovered_at TIMESTAMP NOT NULL` | | |
| `expires_at TIMESTAMP NOT NULL` | | discovered_at + TTL |
| `error_message TEXT` | | last failure (if recent discovery failed) |
| `UNIQUE(backend_kind, auth_method)` | | one cache row per (backend, auth) pair |

Indices on `expires_at` (background-refresh sweep) and `discovered_at` (debug).

### Service layer

New module `app/services/model_cache_service.py`:

```python
def get_models(
    *,
    backend_kind: str,
    auth_method: str,
    force_refresh: bool = False,
) -> tuple[list[str], dict]:
    """Return (models, metadata). Reads from cache; refreshes on miss/expiry/force."""

def refresh(backend_kind: str, auth_method: str) -> dict:
    """Force discovery + cache write. Returns the metadata dict."""

def list_stale(grace_seconds: int = 0) -> list[dict]:
    """Cache entries whose expires_at <= now + grace. Used by the background job."""

def invalidate(backend_kind: str, auth_method: str | None = None) -> int:
    """Delete one or all auth-method rows for a backend kind. Called on auth change."""
```

The existing `ModelDiscoveryService._discover_raw` keeps doing the actual subprocess/PTY/file probing — `model_cache_service` wraps it and adds **auth-method-aware filtering** (see below).

### Auth-method filtering

A small constant table per backend lists which models are gated by which auth method:

```python
# app/services/model_auth_constraints.py
_API_KEY_ONLY_MODELS = {
    "codex": {"gpt-5.1", "gpt-5.1-codex-mini"},  # CLIProxyAPI rejects these on ChatGPT auth
    # claude, gemini, opencode: no known API-key-only models today
}

def filter_models(backend_kind: str, auth_method: str, models: list[str]) -> list[str]:
    """Drop models that the given auth method cannot serve."""
```

`get_models()` applies the filter before returning.

### Background refresh

Add `refresh_stale_model_caches_job()` to `app_litestar/lifecycle.py`:
- Runs daily (mirror v0.7.1 / v0.7.7 TTL job pattern)
- Finds rows with `expires_at <= now() + 24h` (refresh slightly ahead of expiry so users never miss the cache)
- Calls `model_cache_service.refresh(...)` for each — failures are logged, not raised
- Honors env `MODEL_DISCOVERY_TTL_DAYS` (default 7)

### Endpoints

`app_litestar/routes/model_cache.py`:
- `GET /admin/backends/{backend_kind}/models` — cached list (with auth_method query param; defaults to "unknown")
- `POST /admin/backends/{backend_kind}/models/refresh?auth_method=...` — force-refresh
- `GET /admin/backends/models/cache` — admin overview: all rows + freshness
- All admin-guarded.

The existing `discover-models` route on the backend-detail surface stays put as a thin pass-through (so wave-2 callers still work) — internally it calls `get_models()`.

### Frontend

- **"Refresh models" button** on `BackendDetailPage.vue` (or `BackendInfoSection.vue` if cleaner) — fires POST to `/refresh`, shows the new list inline.
- **Per-account auth method awareness** in compound mode: when an account is registered, persist its auth_method. Compound dispatch uses the cached models filtered by that auth method.

### Auth invalidation

When a backend account is created or its auth method changes (e.g. user switches from API key to OAuth), invalidate the cache row for that (kind, auth_method) pair via `model_cache_service.invalidate(...)`. Wire this from the existing account-creation/-update path.

## Out of scope

- Cross-backend "best model for this task" recommendation
- Per-team model preferences
- Real-time SSE on cache updates (poll on view)
- Model deprecation timestamps (provider-published)
- Migrating EXISTING hardcoded model lists in views — those continue to work via the cache (just slower until first refresh)
