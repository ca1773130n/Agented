# v0.5.15 — Backups (design)

E-E piece. Provide a deterministic, online backup procedure for the
two SQLite databases (`agented.db` + `ai_accounts.db`), an optional
off-site sync hook, scheduled-backup templates, and a restore
procedure.

## Goals

- Operator can produce a point-in-time consistent snapshot of both
  databases with `just backup` while the app is running, no
  service stop required.
- Snapshots are timestamped and written to a configurable directory.
  An optional `BACKUP_REMOTE_CMD` env var pipes each snapshot to an
  operator-chosen off-site target (rclone / aws-cli / scp / rsync).
- Retention policy: snapshots older than `BACKUP_RETENTION_DAYS`
  (default 30) are removed locally after each successful run.
- Operator can restore via `just restore` — picks a snapshot, takes
  a pre-restore safety snapshot of the current DB, then overwrites.
- Schedules are configured via cron / launchd / systemd-timer
  templates the operator wires up themselves (consistent with
  v0.5.13 service templates).

## Non-goals

- Continuous WAL streaming (litestream). Out of scope for v0.5.15;
  the snapshot model is sufficient for a single-operator tool.
- Cloud-specific SDKs (boto3, google-cloud-storage). The
  `BACKUP_REMOTE_CMD` shells out so the operator picks their tool.
- Encryption-at-rest of snapshots. Operator-managed (file
  permissions, encrypted volume, GPG-pre-upload script).
- Automated periodic restoration drills.
- Backup of the on-disk vault keys file (`AGENTED_VAULT_KEYS`,
  `AI_ACCOUNTS_VAULT_KEY`) — those live in env / Keychain /
  Docker secrets per `docs/deploy/SECRETS.md`. Backups capture
  the encrypted DB; the operator must back up keys separately.

## Architecture

```

backend/tests/test_backup.py     unit tests for snapshot + retention

                                   AGENTED_BACKUP_DIR

                                   BACKUP_RETENTION_DAYS

```

## Components

### `scripts/backup.py`

Standalone CLI. Module exposes:

- `BACKUP_TARGETS = [("agented", agented_db_path), ("ai_accounts", ai_accounts_db_path)]` — discovered at runtime via env (`AGENTED_DB_PATH`, plus `./ai_accounts.db` from sidecar's CWD).
- `snapshot_one(label, source_path, dest_dir, *, timestamp) -> Path` — uses Python's `sqlite3.Connection.backup()` API for atomic online snapshot.
- `apply_retention(dest_dir, retention_days, *, label) -> int` — removes files matching `f"{label}-*.db"` older than the cutoff. Returns count removed.
- `sync_remote(snapshot_path, remote_cmd) -> bool` — shells out
  `BACKUP_REMOTE_CMD` with `{file}` replaced by the snapshot path.
  Returns True on exit 0, False otherwise.
- `main(argv)` — orchestrates: for each target, snapshot → retention → optional remote sync. Emits JSON summary on stdout.

CLI flags: `--target {agented|ai_accounts|all}` (default all),
`--retention-days N` (overrides env), `--remote-cmd CMD`
(overrides env), `--no-remote` (skip remote even if env is set),
`--quiet` (no JSON summary), `--dest-dir PATH` (overrides env).

Snapshot filename format: `{label}-{ISO-8601-utc}.db`, e.g.
`agented-2026-05-04T22-30-15Z.db`. Colons replaced with `-` for
filename compatibility.

### `scripts/restore.py`

Standalone CLI. Module exposes:

- `list_snapshots(dest_dir, label) -> list[Path]` — sorted newest-first.
- `restore_one(label, snapshot_path, target_path, *, safety_dir) -> Path` —
  takes a pre-restore snapshot of `target_path` to `safety_dir/{label}-pre-restore-{ts}.db`,
  then copies `snapshot_path` over `target_path`.
- `main(argv)` — interactive: list latest 10 snapshots, prompt
  user. Or `--snapshot PATH` for non-interactive.

CLI flags: `--target {agented|ai_accounts}` (required if not
`--snapshot`), `--snapshot PATH` (skip interactive picker),
`--yes` (skip confirmation prompt), `--no-safety-snapshot`,
`--dest-dir PATH`.

**Service stop required**: restore.py refuses to overwrite a DB
file that has an active `*.db-wal` or `*.db-shm` companion newer
than 60 seconds. Operator instructed via runbook to `just kill`
or `systemctl --user stop agented-backend` first.

### Justfile recipes

```make
# Snapshot both DBs, apply retention, optionally sync to remote.
backup:
    cd backend && uv run python scripts/backup.py

# Restore from snapshot. Stops nothing — operator must shut down first.
restore:
    cd backend && uv run python scripts/restore.py
```

### Scheduling templates

- `scripts/launchd/com.agented.backup.plist` — daily 03:00 local
  time. Operator copies to `~/Library/LaunchAgents/`, edits
  `WorkingDirectory`, runs `launchctl load`.
- `scripts/systemd/agented-backup.service` + `.timer` — daily
  03:00. Operator copies to `~/.config/systemd/user/`, runs
  `systemctl --user enable --now agented-backup.timer`.
- `scripts/cron/backup-crontab.example` — `0 3 * * *` template.

All three templates source the same `.env` and call
`just backup`, so the operator picks one based on platform.

### Env vars (`scripts/check_env.py` + `.env.example`)

Add to `OPTIONAL_VARS`:

- `AGENTED_BACKUP_DIR` — local snapshot directory. Default
  `backend/backups/`. Created lazily by `backup.py`.
- `BACKUP_REMOTE_CMD` — optional shell command template; `{file}`
  is replaced with the snapshot path. Examples:
  `rclone copy {file} agented-backup:` (rclone),
  `aws s3 cp {file} s3://agented-backups/` (aws-cli),
  `scp {file} backup-host:agented/` (scp),
  `rsync {file} backup-host:/backups/agented/` (rsync).
  Unset → no off-site sync.
- `BACKUP_RETENTION_DAYS` — integer, default 30. Snapshots older
  than this many days are removed after each successful run.

### `docs/deploy/BACKUP.md`

Sections:
1. What gets backed up (and what doesn't — vault keys, configs).
2. Manual: `just backup`, output format, exit codes.
3. Off-site sync: `BACKUP_REMOTE_CMD` examples for rclone, aws-cli,
   scp, rsync.
4. Scheduling: launchd / systemd-timer / cron walkthroughs.
5. Restore: `just restore` interactive flow + manual stop required.
6. Verification: how to validate a snapshot
   (`sqlite3 snapshot.db "PRAGMA integrity_check"`).
7. Disaster recovery checklist.

## Data flow

```
just backup
  ↓
scripts/backup.py main()
  ├── for label, src in BACKUP_TARGETS:
  │     dest = $DIR/{label}-{ts}.db
  │     sqlite3.Connection(src).backup(dest_conn)  # atomic, online
  │     apply_retention(dir, days, label=label)
  │     if BACKUP_REMOTE_CMD:
  │         shell.run(cmd.format(file=dest))
  │
  └── emit JSON summary {
        targets: [
          {label: "agented", path, size_bytes, remote_synced: bool},
          {label: "ai_accounts", path, size_bytes, remote_synced: bool},
        ],
        retained: int,
        removed: int,
        elapsed_seconds: float,
      }
```

```
just restore
  ↓
scripts/restore.py main()
  - Detect active DB (refuse if recent WAL/SHM)
  - List snapshots, user picks one
  - Take pre-restore snapshot of current DB to safety_dir
  - cp snapshot → target_path
  - exit 0 with restored summary
```

## Error handling

- `sqlite3.backup()` failure (disk full, source locked too long):
  exit 1 with stderr message; partial snapshots are deleted to
  avoid leaving truncated files.
- `BACKUP_REMOTE_CMD` failure: log WARN, mark `remote_synced: false`
  in the summary, continue. The local snapshot is preserved (the
  whole point of the local copy is to survive a remote outage).
- `apply_retention` failure (e.g., permission denied on a stale file):
  log WARN, continue.
- `restore.py` refusing live DB: exit 2 with a message pointing to
  the service-stop instruction in BACKUP.md.

## Testing

`backend/tests/test_backup.py` — ~8 tests:
1. `snapshot_one` produces a readable copy of a populated DB.
2. Snapshot is atomic — concurrent writer doesn't corrupt the snapshot.
   (Approximated via in-test thread; may be platform-flaky, marked
   `@pytest.mark.flaky` if needed.)
3. `apply_retention` deletes files older than the cutoff.
4. `apply_retention` keeps files newer than the cutoff.
5. `sync_remote` invokes the shell command with `{file}` replaced.
6. `sync_remote` returns False on non-zero exit.
7. CLI: `main()` exits 0 on success.
8. CLI: `main()` exits 1 when source DB doesn't exist.

`backend/tests/test_restore.py` — ~5 tests:
1. `list_snapshots` returns newest-first.
2. `restore_one` creates a pre-restore safety snapshot.
3. `restore_one` overwrites target with snapshot contents.
4. CLI: `--snapshot PATH` is non-interactive.
5. CLI: refuses if `*.db-wal` is newer than 60s (live-DB guard).

## Conventions

- All scripts in `backend/scripts/`, tests in `backend/tests/`.
- Templates in `scripts/launchd/`, `scripts/systemd/`,
  `scripts/cron/` (existing v0.5.13 layout).
- Snapshot filename: `{label}-{ISO-8601-utc-with-Z}.db`.
- ISO timestamp: colons replaced with hyphens (Windows-friendly,
  shell-friendly).
- JSON-on-stdout output for scripted callers; human-readable lines
  on stderr.

## Out of scope

- Continuous replication (litestream).
- Encryption of snapshots before upload.
- Restore-time integrity verification (operator runs
  `PRAGMA integrity_check` per BACKUP.md).
- Cloud-specific automation (S3 lifecycle policies, GCS
  versioning).
- UI for browsing or triggering backups.
