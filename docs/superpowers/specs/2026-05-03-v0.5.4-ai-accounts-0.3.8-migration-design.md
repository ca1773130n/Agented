# v0.5.4 — ai-accounts 0.3.8 migration (bidirectional)

**Date:** 2026-05-03
**Milestone target:** v0.5.4 (patch)
**Status:** design **revised** 2026-05-03 after Phase 0 reconnaissance
surfaced unfinished work. Awaiting implementation plan.

## Phase 0 Finding (added 2026-05-03)

Reconnaissance against `~/Developer/Projects/ai-accounts` 0.3.8 plus
the existing Agented call sites surfaced a fact the original design
missed: **the prior `AiChatPanel` migration was abandoned mid-WIP.**

- Commit `b2ee00d` (2026-04-14, message ends with "(WIP)") replaced
  `frontend/src/components/ai/AiChatPanel.vue` from **837 lines → 36
  lines** as a thin pass-through wrapper around
  `@ai-accounts/vue-styled AiChatPanel`. Same commit deleted 7 sibling
  chat components (AiChatSelector, AllModeResponse, ChatModeSelector,
  CompoundSynthesis, MessageActions, MessageBubble, ProcessGroup —
  2055 lines total).
- The wrapper now accepts only the 13 props that
  `BaseAiChatPanel` accepts (`density, defaultBackend, defaultModel,
  placeholder, welcomeTitle, welcomeSubtitle, readOnly, entityLabel,
  bannerTitle, bannerButtonLabel, showProcessGroups, showActions,
  configParser`) plus the `finalize` emit.
- **All 11 call sites** still pass props matching the deleted 837-line
  API: `:messages`, `:is-processing`, `:streaming-content`,
  `:input-message`, `:conversation-id`, `:can-finalize`,
  `:is-finalizing`, `:init-streaming-parser`, `:show-backend-selector`,
  `:selected-backend`, `:selected-account-id`, `:selected-model`,
  `:assistant-icon-paths`, `:detected-entity-name`, `:use-smart-scroll`,
  `:input-placeholder`, plus events `@update:input-message`,
  `@update:selected-backend`, `@update:selected-account-id`,
  `@update:selected-model`, `@send`, `@keydown`.
- These props/events fall through Vue's `inheritAttrs` to
  `BaseAiChatPanel`'s root element where they are silently dropped.
  `BaseAiChatPanel` falls back to its internal `useSmartChat` state,
  so the chat renders — but it does **not** reflect the
  caller-managed messages/streaming/input state. Each of the 11 pages
  is currently rendering a generic chat that ignores its caller's data.

**Affected pages:** SketchChatPage, PluginDesignPage, RuleDesignPage,
WorkflowPlaygroundPage, ProjectManagementPage, HookDesignPage,
CommandDesignPage, AIBackendsPage, SuperAgentPlayground,
SkillCreateWizard, AgentCreateWizard.

## Path chosen: Z (fat translation wrapper) for v0.5.4

The original spec assumed a clean pin-bump migration. Three response
paths were evaluated:

- **X — Restore-and-bump.** Revert `b2ee00d`, bring back the 837-line
  AiChatPanel + 7 deleted siblings, then bump to 0.3.8 against that
  surface. Rejected — recreates the duplicate-with-`vue-styled`
  problem the WIP was trying to remove.
- **Y — Finish the WIP per page.** Re-architect each of the 11 call
  sites to consume `BaseAiChatPanel`'s smart-chat-managed state model.
  Real fix, but ~11 page-rewrites and a per-page design pass each.
  Doesn't fit a patch milestone.
- **Z — Fat translation wrapper.** Grow Agented's
  `frontend/src/components/ai/AiChatPanel.vue` from a 36-line
  pass-through into a translator that accepts the *old* 837-line prop
  surface and drives `useSmartChat` (and a small set of internal
  computed state) accordingly. Each call site stays as-is. Restores a
  working integration today; pays the design debt later via Y.

**v0.5.4 ships path Z.** v0.5.5+ is the per-page Y track, scoped
separately.

## Goal (revised)

1. Restore caller-managed state semantics for AiChatPanel by
   reimplementing the Agented wrapper as a translation layer between
   the old 837-line consumer API and `@ai-accounts/vue-styled
   BaseAiChatPanel` + `@ai-accounts/vue-headless useSmartChat`.
2. Bump the `@ai-accounts/*` and `ai-accounts-*` pins to whatever
   version is current locally (registry 0.3.8 if cut, otherwise the
   working `file:` checkout that contains 0.3.8 commits).
3. Audit project-independent code in Agented and upstream it to
   ai-accounts (path 2 from the original goal — unchanged).

This is still a patch milestone, but the central deliverable shifts
from "pin bump + call-site renames" to "translation wrapper that
makes the existing call sites work again". No new mount points, no
new routes, no new pages.

## Background

ai-accounts is the sibling repo at `~/Developer/Projects/ai-accounts`,
pinned in Agented as local `file:` / editable paths. Tags `v0.3.3`
through `v0.3.8` are out (CHANGELOG only documents through 0.3.2; the
rest is reconstructed from commits). Significant 0.3.8 content:

- CLI version compatibility for Claude / Codex / Gemini / OpenCode
- Security wave 3 — SSRF guard, typed exceptions, OAuth-code redaction
- AccountWizard polish (eager paste-code form, per-element tour
  spotlights, account-name optional)
- **Chat panel landing** — vue-styled `AiChatPanel`, polish, account
  labels, session reset, real-model fan-out, single-mode token field
  rename
- SSE plumbing — UrlPrompt replay, CRLF normalize, init-order 401 fix

Agented already integrates `@ai-accounts/*` extensively:

- `frontend/src/components/ai/AiChatPanel.vue` — wrapper around
  `@ai-accounts/vue-styled AiChatPanel`
- `frontend/src/composables/useAiChat.ts` — re-exports `useSmartChat`,
  `useProcessGroups`, `useStreamingParser` from `vue-headless`
- `frontend/src/views/SketchChatPage.vue` — sketch→implementation flow
- `frontend/src/main.ts` — `aiAccountsPlugin` mounted globally
- `frontend/src/views/BackendDetailPage.vue` — `AccountWizard`
- `backend/pyproject.toml` — `ai-accounts-core`, `ai-accounts-litestar`

So this is **API migration**, not feature integration.

## Non-goals

- New ChatPanel mount points (e.g., a `/playground` page or per-agent
  chat tab). Captured as P1–P5 candidates for v0.5.5+.
- AccountWizard visual restyle to match Agented's Geist theme beyond
  what's strictly required to render. Theming alignment is its own pass.
- Slot/template additions to existing AiChatPanel call sites beyond
  what each one already uses.
- Backend (Python) refactors not directly forced by the
  `ai-accounts-core` / `ai-accounts-litestar` API delta.

## Architecture

No architectural changes. No new components, no new routes, no new
composables, no new database tables.

## Approach

**A2 (reconnaissance) → A1 (execute).**

### Phase 0 — Reconnaissance (~30 minutes)

Read just the chat-panel + wizard + plumbing commits in 0.3.8 to
write down the API deltas explicitly:

- Renamed props/events (e.g., `tokens` → `singleModeTokens`)
- New required props that didn't exist before
- New optional props worth adopting (account labels, session reset)
- Behavior-only changes that could affect consumers silently
  (default-backend selection, token streaming format)

Output: a checklist file (informal, not committed) that drives Phase 1.

### Phase 1 — Translation wrapper + pin bump (the patch itself)

#### 1a. Translation wrapper (the central deliverable)

Rewrite `frontend/src/components/ai/AiChatPanel.vue` so it accepts the
old 837-line consumer API and drives `BaseAiChatPanel` + `useSmartChat`
correctly. The wrapper's *consumer surface* is fixed by what the 11
existing call sites pass; the wrapper's *internal* implementation
follows `BaseAiChatPanel`'s state model.

**Consumer-facing props the wrapper must accept** (from the 11 call
sites — exact spelling preserved, kebab + camel both supported by Vue
prop convention):

- Caller-managed state: `messages`, `isProcessing` (`is-processing`),
  `streamingContent` (`streaming-content`), `inputMessage`
  (`input-message`), `conversationId` (`conversation-id`),
  `canFinalize` (`can-finalize`), `isFinalizing` (`is-finalizing`)
- Backend selector state: `selectedBackend` (`selected-backend`),
  `selectedAccountId` (`selected-account-id`), `selectedModel`
  (`selected-model`), `showBackendSelector` (`show-backend-selector`)
- Display: `inputPlaceholder` (`input-placeholder`), `entityLabel`
  (`entity-label`), `bannerTitle` (`banner-title`), `bannerButtonLabel`
  (`banner-button-label`), `assistantIconPaths`
  (`assistant-icon-paths`), `detectedEntityName`
  (`detected-entity-name`), `useSmartScroll` (`use-smart-scroll`)
- Streaming hook: `initStreamingParser` (`init-streaming-parser`)
- Pass-through to BaseAiChatPanel (already supported): `density`,
  `defaultBackend`, `defaultModel`, `placeholder`, `welcomeTitle`,
  `welcomeSubtitle`, `readOnly`, `showProcessGroups`, `showActions`,
  `configParser`

**Consumer-facing events:** `update:inputMessage`,
`update:selectedBackend`, `update:selectedAccountId`,
`update:selectedModel`, `send`, `keydown`, plus existing `finalize`.

**Consumer-facing slots:** `header-extra`, `welcome` (per call sites
inspected). Forward all slots transparently.

**Internal translation strategy:**

The wrapper's job is to bridge two state models — caller-owned
(messages/streaming/input as props) versus `useSmartChat`-owned. The
v0.5.4 design picks the simplest bridge that preserves caller intent:

- The wrapper maintains an *internal* `useSmartChat` instance and
  *suppresses* its built-in input/send UI by composing
  `BaseAiChatPanel` only as a renderer for the caller's `messages`
  prop. If the public `BaseAiChatPanel` API doesn't expose a
  caller-managed-messages render mode, the wrapper renders the message
  list itself using `ChatBubble` (re-exported from
  `@ai-accounts/vue-styled`) and uses `BaseAiChatPanel` only for the
  input/controls strip — or, conversely, bypasses `BaseAiChatPanel`
  entirely and renders the styled subcomponents directly. The exact
  composition is decided in Phase 1a Task 1 (recon against the
  vue-styled subcomponent exports) and committed before any call-site
  test runs.
- Backend/account/model selection is forwarded to `useSmartChat`'s
  reactive `selectedBackend` / `selectedAccount` / `selectedModel`
  refs, with `update:*` events emitted on changes so callers stay in
  sync.
- `send` is the caller's responsibility — the wrapper emits the event
  but does *not* call `useSmartChat.send()`. Callers (which already
  manage messages/streaming themselves) drive their own send logic.
- `streamingContent` is rendered as an in-flight bubble appended to
  `messages` when non-empty. Visual parity with the deleted 837-line
  component, not byte-identical.
- `keydown` is a passthrough on the input element.

The 0.3.8 BackendOption shape change (`accounts: string[]` →
`Array<{id, label}>`) is consumed via `useSmartChat`'s reactive
`backendOptions`, so the wrapper does not need to handle it directly.

#### 1b. useAiChat composable surface

`frontend/src/composables/useAiChat.ts` currently re-exports
`useSmartChat`, `useProcessGroups`, `useStreamingParser` (and types)

against 0.3.8; add exports for any new types the wrapper or call sites
need (e.g., `BackendAccountOption`, `CliproxyLoginStatus`).

#### 1c. Pin bump

- `backend/pyproject.toml` — `ai-accounts-core`, `ai-accounts-litestar`

  the local checkout already contains 0.3.8 commits. If 0.3.8 is cut to
  registry, this is a no-op for v0.5.4 and the registry switch becomes
  a separate `chore:` commit.
- `frontend/package.json` — same approach for `@ai-accounts/ts-core`,
  `@ai-accounts/vue-headless`, `@ai-accounts/vue-styled`. Run
  `npm run build` in `~/Developer/Projects/ai-accounts` first so
  Agented sees regenerated `dist/`.

#### 1d. Test stubs

`frontend/src/test/setup.ts` — update the `AiChatPanel` test stub to
declare the full consumer-facing prop surface so unit tests don't
regress when call sites are rendered through `mount`/`shallowMount`.

E2E baseline check: `npx playwright test e2e/tests/tour-flow.spec.ts`

### Phase 2 — Back-migration audit

Walk this list; classify each as *Agented-specific* /
*project-independent* / *mixed*. Criterion for project-independence:
the code references no Agented domain types (`Bot`, `Agent`, `Sketch`,
`Project`, `Trigger`, `Conversation` entities, Litestar route paths,
Vite proxy paths, Geist theme tokens).

Audit candidates:

- `frontend/src/components/ai/AiChatPanel.vue` — the "thin wrapper".
  If pure pass-through: delete it; have call sites import directly
  from `@ai-accounts/vue-styled`. If it adds a generic preset:
  upstream the preset.
- `frontend/src/composables/useAiChat.ts` — currently pure re-export.
  Likely deletable; call sites import from `@ai-accounts/vue-headless`.
- `frontend/src/composables/useConversation.ts` — probably Agented-
  specific (entity-based conversation API). Quick read to confirm;
  if any sub-utility is generic (SSE chunk-merging, message-list
  state machine), extract upstream into `vue-headless`.
- `frontend/src/composables/useConversationBranch.ts` — likely
  Agented-specific (triggers / branch navigator). Confirm + skip.
- Anything else the audit surfaces (markdown helpers, streaming
  parsers, account-list utilities).

Process per candidate marked project-independent or mixed-with-
extractable-core:

1. Open a PR against `~/Developer/Projects/ai-accounts` adding the
   code to the right package: `vue-styled` for UI, `vue-headless`
   for composables, `ts-core` for client/types, `core` for Python.
2. Wait for upstream release (target: ai-accounts 0.3.9).
3. The Agented-side deletion lands in v0.5.4 only if the upstream
   release lands in time. Otherwise the deletion slips to v0.5.5;
   v0.5.4 still ships as the clean 0.3.8 forward-migration.

## Risk

**Forward direction.** Bounded: vue-tsc surfaces most prop/event
deltas at compile time; existing E2E modal test catches the highest-
risk regression class (AccountWizard interactivity during tour). The
unknown is silent behavior change in `useSmartChat` / streaming
event format. Mitigation: read the relevant 0.3.8 commits in Phase 0
before flipping pins.

**Back-migration direction.** Extracting code that *looks* generic but
has hidden Agented assumptions. Mitigation: each upstream PR's
review in ai-accounts is the gate — if the reviewer flags coupling,
leave the code in Agented and document why in this file.

**Schedule risk on the upstream release.** If 0.3.9 doesn't cut in
time, the Agented-side deletions slip to v0.5.5. v0.5.4 still ships
clean as the 0.3.8 forward-migration; back-migration audit + upstream
PRs land separately.

## Out of scope (deferred)

- **Path Y — per-page migration to BaseAiChatPanel's smart-chat-managed
  state model.** This is the real long-term fix for the WIP
  `b2ee00d` started. Each of the 11 call sites needs its own design
  pass to decide what "caller-managed messages" should map to under
  the smart-chat model. v0.5.4 buys time via path Z; v0.5.5+ executes
  Y, ideally one or two pages per patch.
- New chat-panel mount points (P1 standalone playground, P2 per-agent
  chat tab, P3 sidebar drawer, P4 project-scoped, P5 conversations
  follow-up) — v0.5.5+ with own design pass.
- AccountWizard visual theming alignment to Geist — separate pass.
- Backend chat-side adoption (e.g., consuming
  `ai_accounts_core.services.chat.ChatService` to expose a
  `/api/agents/:id/chat` route) — separate milestone.
