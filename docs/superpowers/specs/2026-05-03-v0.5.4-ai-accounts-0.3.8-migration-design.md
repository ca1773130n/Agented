# v0.5.4 — ai-accounts 0.3.8 migration (bidirectional)

**Date:** 2026-05-03
**Milestone target:** v0.5.4 (patch)
**Status:** design approved, awaiting implementation plan

## Goal

Migrate Agented to consume ai-accounts 0.3.8 across all existing
consumers, *and* upstream any project-independent functionality that
has accumulated in Agented back to ai-accounts.

This is a patch milestone, not a feature milestone: no new mount
points, no new routes, no new composables.

## Background

ai-accounts is the sibling repo at `~/Developer/Projects/ai-accounts`,
pinned in Agented as local `file:` / editable paths. Tags `v0.3.3`
through `v0.3.8` are out (CHANGELOG only documents through 0.3.2; the
rest is reconstructed from commits). Significant 0.3.8 content:

- CLI version compatibility for Claude / Codex / Gemini / OpenCode
- Security wave 3 — SSRF guard, typed exceptions, OAuth-code redaction
- AccountWizard polish (eager paste-code form, per-element tour
  spotlights, account-name optional)
- **Chat panel landing** — vue-styled `AiChatPanel`, polish, account
  labels, session reset, real-model fan-out, single-mode token field
  rename
- SSE plumbing — UrlPrompt replay, CRLF normalize, init-order 401 fix

Agented already integrates `@ai-accounts/*` extensively:

- `frontend/src/components/ai/AiChatPanel.vue` — wrapper around
  `@ai-accounts/vue-styled AiChatPanel`
- `frontend/src/composables/useAiChat.ts` — re-exports `useSmartChat`,
  `useProcessGroups`, `useStreamingParser` from `vue-headless`
- `frontend/src/views/SketchChatPage.vue` — sketch→implementation flow
- `frontend/src/main.ts` — `aiAccountsPlugin` mounted globally
- `frontend/src/views/BackendDetailPage.vue` — `AccountWizard`
- `backend/pyproject.toml` — `ai-accounts-core`, `ai-accounts-litestar`

So this is **API migration**, not feature integration.

## Non-goals

- New ChatPanel mount points (e.g., a `/playground` page or per-agent
  chat tab). Captured as P1–P5 candidates for v0.5.5+.
- AccountWizard visual restyle to match Agented's Geist theme beyond
  what's strictly required to render. Theming alignment is its own pass.
- Slot/template additions to existing AiChatPanel call sites beyond
  what each one already uses.
- Backend (Python) refactors not directly forced by the
  `ai-accounts-core` / `ai-accounts-litestar` API delta.

## Architecture

No architectural changes. No new components, no new routes, no new
composables, no new database tables.

## Approach

**A2 (reconnaissance) → A1 (execute).**

### Phase 0 — Reconnaissance (~30 minutes)

Read just the chat-panel + wizard + plumbing commits in 0.3.8 to
write down the API deltas explicitly:

- Renamed props/events (e.g., `tokens` → `singleModeTokens`)
- New required props that didn't exist before
- New optional props worth adopting (account labels, session reset)
- Behavior-only changes that could affect consumers silently
  (default-backend selection, token streaming format)

Output: a checklist file (informal, not committed) that drives Phase 1.

### Phase 1 — Forward migration (the patch itself)

Files modified:

- `backend/pyproject.toml` — flip `ai-accounts-core`,
  `ai-accounts-litestar` to whatever pinning convention v0.5.4 picks
  (continue editable `file:` if dev iteration matters; switch to
  registry version if stability matters). Default: stay on `file:`,
  rebuild via `just deploy` per current CLAUDE.md guidance.
- `frontend/package.json` — same approach for `@ai-accounts/ts-core`,
  `@ai-accounts/vue-headless`, `@ai-accounts/vue-styled`.
- `frontend/src/components/ai/AiChatPanel.vue` — re-align wrapper
  props/events to new BaseAiChatPanel surface.
- `frontend/src/composables/useAiChat.ts` — re-align re-export surface;
  may add new exports if 0.3.8 introduced anything consumers want.
- Each existing AiChatPanel / useSmartChat call site in `frontend/src`
  — apply prop renames; add new optional props if useful.
- `frontend/src/test/setup.ts` — update `AiChatPanel` test stub if its
  prop set changed.

Verification: `just build` + `cd backend && uv run pytest` +
`cd frontend && npm run test:run`. All three must pass.

### Phase 2 — Back-migration audit

Walk this list; classify each as *Agented-specific* /
*project-independent* / *mixed*. Criterion for project-independence:
the code references no Agented domain types (`Bot`, `Agent`, `Sketch`,
`Project`, `Trigger`, `Conversation` entities, Litestar route paths,
Vite proxy paths, Geist theme tokens).

Audit candidates:

- `frontend/src/components/ai/AiChatPanel.vue` — the "thin wrapper".
  If pure pass-through: delete it; have call sites import directly
  from `@ai-accounts/vue-styled`. If it adds a generic preset:
  upstream the preset.
- `frontend/src/composables/useAiChat.ts` — currently pure re-export.
  Likely deletable; call sites import from `@ai-accounts/vue-headless`.
- `frontend/src/composables/useConversation.ts` — probably Agented-
  specific (entity-based conversation API). Quick read to confirm;
  if any sub-utility is generic (SSE chunk-merging, message-list
  state machine), extract upstream into `vue-headless`.
- `frontend/src/composables/useConversationBranch.ts` — likely
  Agented-specific (triggers / branch navigator). Confirm + skip.
- Anything else the audit surfaces (markdown helpers, streaming
  parsers, account-list utilities).

Process per candidate marked project-independent or mixed-with-
extractable-core:

1. Open a PR against `~/Developer/Projects/ai-accounts` adding the
   code to the right package: `vue-styled` for UI, `vue-headless`
   for composables, `ts-core` for client/types, `core` for Python.
2. Wait for upstream release (target: ai-accounts 0.3.9).
3. The Agented-side deletion lands in v0.5.4 only if the upstream
   release lands in time. Otherwise the deletion slips to v0.5.5;
   v0.5.4 still ships as the clean 0.3.8 forward-migration.

## Verification

All three commands must pass:

1. `just build` (vue-tsc + vite build, no errors)
2. `cd backend && uv run pytest` (current baseline: 2196 passed)
3. `cd frontend && npm run test:run` (current baseline: 1069 passed)

E2E baseline check (smoke):

- `npx playwright test e2e/tests/tour-flow.spec.ts` — the
  modal-interaction test added in v0.5.3 exercises the AccountWizard
  through the tour. A regression in 0.3.8 wizard wiring would surface
  here.

No new tests required by the migration. Existing tests update only if
a prop rename touches a tested behavior — change the test in step,
not the assertion.

## Risk

**Forward direction.** Bounded: vue-tsc surfaces most prop/event
deltas at compile time; existing E2E modal test catches the highest-
risk regression class (AccountWizard interactivity during tour). The
unknown is silent behavior change in `useSmartChat` / streaming
event format. Mitigation: read the relevant 0.3.8 commits in Phase 0
before flipping pins.

**Back-migration direction.** Extracting code that *looks* generic but
has hidden Agented assumptions. Mitigation: each upstream PR's
review in ai-accounts is the gate — if the reviewer flags coupling,
leave the code in Agented and document why in this file.

**Schedule risk on the upstream release.** If 0.3.9 doesn't cut in
time, the Agented-side deletions slip to v0.5.5. v0.5.4 still ships
clean as the 0.3.8 forward-migration; back-migration audit + upstream
PRs land separately.

## Out of scope (deferred)

- New chat-panel mount points (P1 standalone playground, P2 per-agent
  chat tab, P3 sidebar drawer, P4 project-scoped, P5 conversations
  follow-up) — v0.5.5+ with own design pass.
- AccountWizard visual theming alignment to Geist — separate pass.
- Backend chat-side adoption (e.g., consuming
  `ai_accounts_core.services.chat.ChatService` to expose a
  `/api/agents/:id/chat` route) — separate milestone.

## Success criteria

1. `just build` + backend pytest + frontend vitest all green on
   `feat/v0.5.4-ai-accounts-0.3.8` branch.
2. Existing AiChatPanel call sites render and stream correctly.
3. AccountWizard tour modal E2E (v0.5.3) still passes.
4. The `frontend/src/components/ai/` and
   `frontend/src/composables/` directories are *no larger* in Agented
   than before — anything project-independent is upstream or staged
   to upstream.
5. v0.5.4 git tag pushed; STATE.md marks the milestone complete.
