# v0.7.9 — Authoritative Model Discovery via Sidecar

## Goal

Stop populating the model dropdown from `~/.claude/stats-cache.json modelUsage` (i.e. the user's *personal usage history*). Replace with the authoritative provider catalog by routing discovery through the **ai-accounts sidecar's existing `/api/v1/backends/{id}/models` endpoint**, which already calls each backend's `list_models(credential)` against the real provider API (Anthropic, OpenAI/Codex, Google, OpenCode).

## What's wrong now

User reports: Claude detail page shows only `Opus 4.6 / Sonnet 4.6 / Haiku 4.5` — these are exactly the 3 models in the user's `stats-cache.json modelUsage` (i.e. models THEY'VE USED). The discovery chain in `ModelDiscoveryService._discover_raw("claude")`:

1. `_discover_claude_models_local()` — reads `stats-cache.json` ← **only used models** ← user's bug
2. PTY parse — current model only
3. CLIProxyAPI live — empty if proxy not running
4. OpenCode list — empty if opencode not installed

For other backends the story is the same: chain is biased toward CLI artifacts on disk, not the provider's real catalog.

Meanwhile the sidecar's `account_service.list_models(backend_id)` already:
- For Claude, hits `cliproxy_list_models("claude")` then falls back to a curated 10-model list (Opus 4.6 → 3.5 Haiku)
- For Codex, hits OpenAI's `/v1/models` (with the stored credential) — see `codex.py::list_models`
- For Gemini, hits `https://generativelanguage.googleapis.com/v1beta/models?key=…` — already authoritative
- For OpenCode, queries the local config

It's already exposed on the sidecar at `GET /api/v1/backends/{backend_id}/models`. Just unused by Agented's discovery chain.

## Architecture

### New discovery path: `_discover_via_sidecar`

`ModelDiscoveryService` gains a single new method:

```python
@classmethod
def _discover_via_sidecar(cls, backend_kind: str, auth_method: str) -> list[str] | None:
    """Hit the ai-accounts sidecar's /api/v1/backends/{id}/models endpoint
    using a representative account for this (kind, auth_method) pair.
    Returns model IDs or None on failure (caller continues the chain)."""
```

Implementation:
1. Find a backend_account in the local DB matching (kind, auth_method). If none, return None.
2. Build the sidecar URL: `http://127.0.0.1:20001/api/v1/backends/{account_id}/models`
3. Pass through `AI_ACCOUNTS_API_KEY` / admin token in the `X-API-Key` header (mirror existing sidecar calls in `backend_management` services).
4. httpx GET with `timeout=10.0`. On 200, parse `{items: [{id, display_name, context_window}, ...]}` into `[id, ...]`. On non-200 or network error, return None (don't poison the cache — `model_cache_service` already shortens TTL on empty results).
5. Add a `discovery_method` value of `"sidecar"` so the operator UI can show the source.

### Chain reorder per backend

Move sidecar to the **front** of every backend's discovery chain. Existing logic stays as fallback:

```python
elif backend_type == "claude":
    models = cls._discover_via_sidecar("claude", auth_method)
    if not models:
        models = cls._discover_claude_models_local()
    if not models:
        models = cls._discover_claude_models_pty()
    # Existing merge with cliproxy + opencode stays as is
    ...
```

Same pattern for codex/gemini/opencode.

### Auth-method threading

`_discover_raw` currently takes only `backend_type`. v0.7.8 added auth-method awareness to `model_cache_service` but the underlying discovery is auth-method-blind. Extend `_discover_raw` to optionally accept `auth_method` (default `"unknown"`), used only for the sidecar account-selection step. Callers (model_cache_service.py) pass it through.

### Cache integration

Already done. v0.7.8's `model_cache_service.get_models(backend_kind, auth_method)` wraps `_discover_raw`. The new sidecar path inherits the 7-day TTL + 1-hour error TTL + manual refresh + daily background refresh.

### Discovery-method telemetry

`_discover_and_store` already records `discovery_method`. Today it's always `"mixed"`. Update to record the *first successful* source: `"sidecar"`, `"local"`, `"pty"`, `"cliproxy"`, `"opencode"`, or `"empty"`. The Inspector + admin overview surface this so operators know whether they're seeing the authoritative list or a fallback.

## Tests

- `test_model_discovery_sidecar_path.py`:
  - Sidecar 200 response → returns the models, marks discovery_method="sidecar"
  - Sidecar 500 → returns None, chain continues to local
  - Sidecar timeout → returns None, no cache poison
  - No matching account → returns None
- Existing `_discover_claude_models_local` etc tests untouched
- `test_model_cache_service.py` — assert that `get_models` after `refresh` reports `discovery_method="sidecar"` when sidecar returns data

## Out of scope

- Improving the sidecar's `list_models()` impls themselves — that's per-backend in ai-accounts and a separate effort
- Multi-account aggregation (one cache row per kind+auth_method, not per account)
- Models that vary BY ACCOUNT within the same auth_method (rare; if needed, address in v0.7.10)
- A "models registry" mirror — provider endpoints are the source
