# Documentation i18n convention

This repo's prose documentation is multi-language across **two** surfaces,
each with its own locale convention:

| Surface | Location | Locale convention | Switcher |
|---|---|---|---|
| **VitePress docs site** | `docs/` | directory-based (`docs/` = en, `docs/ko/` = ko) | page-level language dropdown (built into VitePress) |
| **Root-level standalone essays** | repo root, e.g. `BLOG-*.md` | locale-**suffix** siblings (`*.ko.md`) | manual header line, renders natively on GitHub |

Both surfaces share the same translation discipline (below). They differ
only in *where the locale lives in the path*.

## VitePress docs site (`docs/`) — directory-based

The docs site is a VitePress project rooted at `docs/`. Locales are
directory-based so VitePress can drive a page-level language dropdown by
path prefix:

- **English (canonical)** lives at the root of `docs/` — e.g.
  `docs/self-improving-harness-architecture.md`.
- **Korean** mirrors it under `docs/ko/` — e.g.
  `docs/ko/self-improving-harness-architecture.md`.

`docs/.vitepress/config.ts` declares the `root` (English) and `ko`
locales; the dropdown and per-locale nav/sidebar come from there. The
per-page manual language header is kept too (harmless alongside the
dropdown, and it helps people reading the file directly on GitHub) —
but it points at VitePress-relative paths:

```markdown
<!-- in docs/self-improving-harness-architecture.md -->
**Languages:** English (canonical) · [한국어](/ko/self-improving-harness-architecture)
```

```markdown
<!-- in docs/ko/self-improving-harness-architecture.md -->
**언어:** [English](/self-improving-harness-architecture) · 한국어 (현재)
```

Pre-existing internal planning/spec/report markdown under `docs/`
(`docs/superpowers/`, `docs/plans/`, `docs/deploy/`, etc.) is **not**
part of the public site — it's excluded via `srcExclude` in the config.

### Commands

```bash
cd docs
npm install
npm run dev       # local dev server (vitepress dev) — blocks
npm run build     # production build (vitepress build) — dead-link check on
npm run preview   # serve the built site (vitepress preview)
```

## Root-level standalone essays — locale-suffix siblings

Standalone essays that live at the **repo root** (outside the VitePress
`srcDir`) keep the **locale-suffix** convention — zero build tooling,
renders natively on GitHub:

1. **English is canonical.** `foo.md` is the source of truth.
2. **Translations are siblings with a locale suffix:** `foo.<locale>.md`
   (BCP-47 short code). Korean → `foo.ko.md`.
3. **Every translatable essay carries a language-switcher header** as the
   first line after the H1:
   ```markdown
   **Languages:** English (canonical) · [한국어](./foo.ko.md)
   ```
   The translated file mirrors it, marking its own language as current:
   ```markdown
   **언어:** [English](./foo.md) · 한국어 (현재)
   ```

## Shared translation discipline (both surfaces)

- **Code is not translated.** Identifiers, file paths, route paths,
  table/column names, CLI commands, env vars, and code blocks stay
  verbatim in every locale. Only prose is translated. The ASCII
  diagrams stay identical.
- **The canonical and every translation stay structurally 1:1** —
  same headings, same order, same tables. A translation that drifts in
  structure is a bug.

## Standing rule

When a new prose document is added under `docs/` (or a top-level
`*.md` essay), a **Korean** version is written alongside it in the same
change — `docs/ko/foo.md` for the docs site, or `foo.ko.md` for a
root-level essay. English-only is incomplete.

## Other doc frameworks

This layout is a strict subset of what the major SOTA doc frameworks
consume:

- **VitePress i18n** — directory-based locale roots (`/<locale>/`); the
  language dropdown is built in. (This is what `docs/` uses.)
- **Docusaurus i18n** — `i18n/<locale>/…` with `docusaurus write-translations`.
- **mkdocs-static-i18n** — supports the `*.ko.md` suffix mode natively
  (`docs_structure: suffix`).

For app/UI strings (not docs), the SOTA choice in this Vue 3 frontend is
**vue-i18n** — a separate concern from prose docs and out of scope for
this convention.
