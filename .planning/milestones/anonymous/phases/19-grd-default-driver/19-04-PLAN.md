  <action>
    Add `class GrdChatSessionHandler` mirroring `GoalLoopSessionHandler.start`
    (execution_type_handler.py:420–537) verbatim except for the command. In `.start`:

      - Determine the grd command from the session_config intent using

        f'{grd_command} "{safe_task}"']` — matching GrdPlanningService.invoke_command's shape.

        directly (do NOT prepend `/grd:` again — the final token must be exactly one
        `/grd:<cmd> "<task>"` string). `safe_task` is the task text with double quotes
        stripped/escaped (e.g. `task.replace('"', "'")`) so user input cannot break out of
        the quoted argument and inject extra slash-command text.
      - Call `ProjectSessionManager.create_session(project_id, cmd, cwd, ...,
        execution_type="grd_chat", stream_json=True, use_pty=False, yolo_mode=...,
        forge_bundle=session_config.get("forge_bundle"),
        super_agent_id=session_config.get("super_agent_id"))` (kwargs already supported,
        project_session_manager.py:835–836).
      - `monitor`/`stop`/`get_output` delegate to ProjectSessionManager exactly as
        GoalLoopSessionHandler does (get_session_info, stop_session, get_output). Ensure `stop`
        stops the PSM session so a chat abort does not orphan it (risk 5).
