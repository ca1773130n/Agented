<objective>
The hybrid gate (REQ-24) — the integration point that ties signal store, scanner,
dedup/provenance, per-project policy, and the skill-create path together.

`evaluate_signal(signal, scan, dedup, provenance, policy) -> GateDecision`: a PURE
function. AUTO iff occurrence_count ≥ 3 within 30 days AND verified_success_count ≥ 1
AND scan clean AND dedup-ok AND provenance-ok AND per-project policy enabled. Weaker
evidence → PROPOSE (operator queue, confidence 0.65). Scan-fail / provenance-diverged
downgrades the AUTO candidate to PROPOSE.

`convert_signal(signal, decision)`: on AUTO, emit a `discovered_procedure` takeaway at
confidence 0.9 (valid kind per harness_takeaways VALID_KINDS:12; insert_many:27) and
create the skill via the evolver `_create_dispatch["skill"]` — the PROVEN path
(test_forge_skill_dispatch.py); `create_and_bind_and_materialize`'s `_CREATE_FNS` does
NOT include "skill" (verified at plan time), so do NOT use it. A near-duplicate routes
to `_update_dispatch["skill"]` (patch-over-create). After create, record origin_hash
and `mark_skill_created`.

AUTONOMY FLAG (verified): the real flag is `AGENTED_TAKEAWAY_AUTOAPPLY`
(harness_takeaway_extractor.py:1033) — NOT `AGENTED_AUTONOMY`. REQ-24 "promote env flag
to per-project policy" = read `project_autonomy_config` for the signal's project first;
fall back to `AGENTED_TAKEAWAY_AUTOAPPLY` only when no project row exists.

Purpose: Convert sufficiently-confident safe recurring signals into skills automatically,
and queue everything else for approval.
Output: One gate module, one parametrized test suite (P2 + A2).
Research basis: 22-RESEARCH.md REQ-24; EVAL P2, A2.
