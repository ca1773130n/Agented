<objective>
Build the one reusable OS-sandbox command-prefix builder (REQ-31). `build_sandbox_prefix` returns an argv PREFIX (bwrap on Linux, `sandbox-exec -p <SBPL>` on macOS) plus a `sandboxed: bool`, so the existing `subprocess.Popen` at every harness site stays put and just gets a prefix — mirroring the `stdbuf` prepend already in place. Detection probes for a *usable* sandbox (handles `unprivileged_userns_clone=0`) and degrades in place to `(cmd, sandboxed=False)` with a logged warning, generalizing the `sandbox_eval.py` pattern beyond deterministic eval checks.

Purpose: a single DRY wrap point so Plan 03 can route ALL harness Popen sites through it and the Phase-23 `enforce_sandbox` gate can read a truthful `sandboxed` flag.
Output: `backend/app/services/sandbox_wrap.py` + unit tests.
Research basis: 24-RESEARCH.md Rec 1 (bwrap argv, exact flags), Rec 2 (SBPL profile, deny-wins quirk), Pitfall 2 (userns probe), §Architecture "prefix-builder, not a new launcher".
</objective>
